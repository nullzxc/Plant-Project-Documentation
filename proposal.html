Pi Plant Watering System

Raspberry Pi monitors soil moisture and controls a relay-driven pump to maintain healthy moisture levels. A Tkinter GUI provides monitoring, manual override, and calibration. This proposal outlines scope, design, milestones, risk mitigation, and evaluation criteria aligned with course requirements.

1) Project Summary

This project automates watering for potted plants using a Raspberry Pi 4. A soil moisture sensor (digital or analog via MCP3008) feeds the Pi; the system actuates a 5V pump through a relay, enforcing max-on time and cooldown to prevent over-watering. The GUI displays live readings, logs events, and allows manual control. We prioritize stability, safety (separate pump PSU), and a clean, user-friendly demo.

2) Objectives & Success Criteria

  • Maintain soil moisture within a configurable range with automatic cycles.
  • Provide a simple GUI for manual watering, threshold (analog mode), and log view.
  • Demonstrate 30–50 stable on/off cycles without Pi brown-outs.
  • Document wiring, software, testing results, and safety measures.

Deliverables

  • Working hardware prototype with relay-controlled pump.
  • Python apps: app_digital.py, app_analog.py, helper modules, and GUI.
  • Documentation website (build notes, troubleshooting, and proposal).
  • Final demo + optional report screenshots/photos.

4) System Design

4.1 Architecture

Soil Sensor (analog) → MCP3008 → SPI → Raspberry Pi → Python Logic
                                        ├─ Tkinter GUI (threshold/logs)
                                        └─ Relay (BCM 23) → Pump + External 5V

Optional: LED (BCM 24), Buzzer (BCM 18)

4.2 Key Design Choices

  • Safety: Pump powered by separate 5V adapter; common ground with Pi.
  • Reliability: Cooldown and max-on timers; active-LOW relay handling.
  • Flexibility: Supports digital or analog sensors via config.
  • Usability: Minimal GUI with clear labels, logs, and manual override.

6) Risks & Mitigation

  • Power brown-outs: Use separate 5V pump PSU; verify common ground; keep Pi PSU ≥3A.
  • Relay logic inversion: Support active-LOW via config; test with click script before pump.
  • Sensor variance: Calibrate thresholds; support both digital and analog modes.
  • Over-watering: Enforce PUMP_SECONDS & COOLDOWN_SECONDS; manual override visible.
  • Water near electronics: Drip loops; keep Pi elevated; test away from the plant first.

7) Evaluation Metrics

  • Functionality: Auto watering triggers correctly in dry conditions; stops when wet.
  • Stability: ≥30 consecutive cycles with no Pi reboot or logic fault.
  • Usability: GUI clarity, manual control responsiveness, useful logs.
  • Safety: Separate PSU for pump; verified common ground; guarded run-time.
  • Documentation: Clear wiring, instructions, troubleshooting, and proposal completeness.

8) Ethics & Safety

We minimize environmental and equipment risk by using low-voltage components, isolating the pump’s supply, and keeping electronics above the water line. We will not collect personal data; logs pertain only to device state. The system will be operated under supervision during testing and demo, with emergency cut-off via relay disable and PSU disconnect.
